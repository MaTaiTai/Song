# 同仁四季椰子鸡餐厅点歌小程序项目需求架构说明书

## 一、项目概述

本项目旨在为“同仁四季椰子鸡”餐厅打造一款功能全面、安全可靠、体验卓越的点歌小程序。该小程序将作为餐厅与顾客、驻场歌手之间的互动桥梁，通过数字化手段提升顾客用餐体验，丰富餐厅的娱乐服务形式，并为驻场歌手提供展示与收益的平台。

### 1.1 项目背景

在餐饮市场竞争日益激烈的当下，单纯的菜品和服务已难以形成绝对的竞争优势。越来越多的餐厅开始探索“餐饮+娱乐”的复合经营模式，以吸引年轻消费群体，增加顾客粘性和用餐时长。“同仁四季椰子鸡”餐厅以其独特的美食和良好的口碑在市场中占据一席之地，为进一步提升品牌影响力和顾客满意度，计划引入点歌互动功能。

### 1.2 项目目标

1.  **提升顾客体验**：为顾客提供便捷、时尚的点歌方式，让用餐过程更加愉悦和个性化。
2.  **赋能驻场歌手**：为驻场歌手提供一个自主上传、管理歌单并获得额外收入的渠道。
3.  **增强餐厅互动性**：通过点歌互动，活跃用餐氛围，增加顾客与餐厅、顾客与歌手之间的互动。
4.  **提升运营效率**：通过数字化管理，简化点歌、支付、分成等流程，降低人工成本。
5.  **构建安全体系**：确保小程序在高并发环境下稳定运行，有效防御各类网络攻击，保障用户数据和交易安全。

## 二、功能需求

### 2.1 用户端

#### 2.1.1 游客端

1.  **扫码进入**：通过扫描餐厅内的二维码，快速进入点歌小程序，无需注册或登录。
2.  **浏览歌单**：可以浏览所有驻场歌手上传的公开歌单。
3.  **查看歌曲详情**：点击歌曲可以查看歌曲名称、歌手、时长、价格等信息。
4.  **支付点歌**：选择歌曲后，可以通过微信或支付宝进行支付，完成点歌。
5.  **消息提示**：支付成功后，收到点歌成功的提示消息。

#### 2.1.2 登录用户端

1.  **登录/注册**：支持微信一键登录，或通过手机号+验证码进行注册登录。
2.  **个人中心**：
    *   查看个人信息（头像、昵称、手机号）。
    *   查看点歌历史记录。
3.  **点歌功能**：除游客端的点歌功能外，登录用户可以享受：
    *   积分或优惠券抵扣,默认为0。
    *   查看点歌队列，了解自己点的歌曲何时播放。
    *   对已播放的歌曲进行评价或点赞。
4.  **互动功能**：
    *   关注喜欢的驻场歌手。
    *   在歌手主页留言或打赏。

### 2.2 驻场歌手端

1.  **注册登录**：在游客界面点击”注册成为歌手“，填写”真实姓名，年龄，手机号，邮箱，密码，确认密码“，使用专属账号密码登录。
2.  **歌单管理**：
    *   **上传歌单**：添加歌曲信息（名称、原唱、时长、价格）。
    *   **编辑歌单**：修改已上传歌曲的信息，或删除歌曲。
    *   **上下架管理**：可以将歌曲设置为“上架”或“下架”状态。
3.  **收益管理**：
    *   查看点歌收益明细（日期、歌曲、收入金额）。
    *   查看累计收益。
    *   申请提现（需绑定微信或支付宝收款账户）。
4.  **个人中心**：
    *   查看和修改个人信息（头像、艺名、简介）。
    *   管理收款账户信息。
    *   查看系统通知。

### 2.3 管理员端

1.  **登录**：使用管理员账号密码登录。
2.  **用户管理**：
    *   查看所有用户列表（游客、注册用户、歌手）。
    *   查看用户详情。
    *   对违规用户进行禁用或拉黑操作。
3.  **歌手管理**：
    *   查看所有驻场歌手列表。
    *   审核歌手的入驻申请。
    *   查看歌手详情和歌单信息。
    *   对违规歌手进行禁用或下架歌单操作。
4.  **订单管理**：
    *   查看所有点歌订单列表。
    *   查看订单详情（用户信息、歌曲信息、支付金额、支付方式、支付状态）。
    *   处理订单相关的售后问题。
5.  **财务管理**：
    *   查看平台总收益。
    *   查看歌手收益分成情况。
    *   处理歌手的提现申请。
    *   生成财务报表。
6.  **系统管理**：
    *   发布和管理系统公告。
    *   设置点歌基础价格、平台分成比例等参数。
    *   管理小程序的配置信息。
    *   查看系统日志。

### 2.4 支付功能

1.  **多平台支付**：支持微信支付和支付宝支付。
2.  **支付流程**：用户选择歌曲后，生成支付订单，调用对应支付平台的SDK完成支付，支付成功后，系统更新订单状态并通知相关用户和歌手。
3.  **退款功能**：支持在一定条件下（如歌曲未播放）进行退款操作。

### 2.5 安全与性能

1.  **高并发支持**：系统架构需支持餐厅高峰期的大量并发用户访问和点歌请求。
2.  **攻击防御**：
    *   防止SQL注入、XSS跨站脚本、CSRF跨站请求伪造等常见Web攻击。
    *   对用户输入进行严格校验。
    *   敏感数据（如用户密码）需进行加密存储。
    *   实现接口访问频率限制，防止恶意请求。
3.  **数据安全**：
    *   定期对数据库进行备份。
    *   建立数据恢复机制。
    *   遵守相关数据保护法规，保障用户隐私。
4.  **性能优化**：
    *   使用Redis缓存热点数据（如热门歌曲、歌单列表），提高响应速度。
    *   对数据库进行合理的索引设计和查询优化。
    *   图片和静态资源使用CDN加速。

## 三、非功能需求

### 3.1 界面设计

1.  **风格**：时尚简约，借鉴国外优秀应用的设计风格，注重留白、排版和用户体验。
2.  **响应式设计**：小程序界面需适配不同尺寸的手机屏幕，确保在各种设备上都有良好的显示效果和操作体验。
3.  **交互设计**：操作流程简洁明了，反馈及时，引导清晰。

### 3.2 兼容性

1.  **平台兼容性**：小程序需同时支持微信小程序和支付宝小程序（或其他主流小程序平台）。
2.  **设备兼容性**：支持主流的iOS和Android操作系统版本。

### 3.3 性能指标

1.  **响应时间**：
    *   页面加载时间：首页和常用功能页面加载时间不超过2秒。
    *   接口响应时间：核心业务接口（如点歌、支付）响应时间不超过1秒。
2.  **并发能力**：系统能够支持至少[200]名用户同时在线操作，点歌请求并发量不低于[50]次/秒。
3.  **稳定性**：系统全年可用性达到99.9%以上。

### 3.4 可维护性

1.  **代码规范**：前后端代码需遵循统一的编码规范，易于阅读和维护。
2.  **模块化设计**：系统采用模块化、组件化设计，便于功能扩展和二次开发。
3.  **日志记录**：完善的日志记录系统，便于排查问题和系统监控。

## 四、技术架构

### 4.1 前端技术栈

*   **框架**：uni-app
*   **UI组件库**：uni-ui 或其他适合uni-app的UI库
*   **状态管理**：Vuex
*   **网络请求**：uni.request
*   **支付集成**：微信支付JSAPI、支付宝小程序支付SDK

### 4.2 后端技术栈

*   **语言**：Java
*   **框架**：Spring Boot
*   **ORM框架**：MyBatis
*   **数据库**：MySQL
*   **缓存**：Redis
*   **API文档**：Swagger/SpringDoc
*   **安全框架**：Spring Security 或 Shiro
*   **支付SDK**：微信支付Java SDK、支付宝支付Java SDK
*   **消息队列**：RabbitMQ 或 RocketMQ（可选，用于处理异步任务，如通知、日志）

### 4.3 部署架构

*   **应用服务器**：Spring Boot 内置Tomcat
*   **Web服务器**：Nginx（用于反向代理、负载均衡、静态资源缓存）
*   **数据库服务器**：MySQL（主从复制架构，提高读写性能和数据安全性）
*   **缓存服务器**：Redis（可采用集群模式，提高可用性和性能）
*   **文件存储**：先存储本地，后续上线后改成阿里云OSS 或 腾讯云COS（用于存储用户头像、歌手照片等图片资源）
*   **CDN**：使用CDN加速静态资源的访问。

## 五、数据库设计

（此处仅列出核心表的设计思路，详细字段需在开发阶段进一步细化）

1.  **用户表 (user)**：存储用户基本信息（ID、昵称、头像、手机号、密码、登录状态等）。
2.  **歌手表 (singer)**：存储歌手基本信息（ID、艺名、头像、简介、入驻状态、收款账户信息等）。
3.  **歌单表 (song_list)**：存储歌单信息（ID、歌手ID、歌单名称、创建时间、更新时间、上下架状态等）。
4.  **歌曲表 (song)**：存储歌曲信息（ID、歌单ID、歌曲名称、原唱、时长、是否收费、价格、播放次数等）。
5.  **订单表 (order)**：存储点歌订单信息（ID、用户ID、歌曲ID、支付金额、支付方式、支付状态、创建时间、支付时间等）。
6.  **收益记录表 (income_record)**：存储歌手收益记录（ID、歌手ID、订单ID、收益金额、记录时间等）。
7.  **提现申请表 (withdraw_apply)**：存储歌手提现申请信息（ID、歌手ID、提现金额、收款账户、申请状态、审核时间、打款时间等）。
8.  **收藏表 (collection)**：存储用户收藏的歌手或歌曲信息（ID、用户ID、关联ID（歌手ID或歌曲ID）、收藏类型、收藏时间等）。
9.  **评价表 (comment)**：存储用户对歌曲的评价信息（ID、用户ID、歌曲ID、评价内容、评分、评价时间等）。

## 七、风险评估与应对

1.  **技术风险**：
    *   **风险**：uni-app跨平台兼容性问题；支付接口集成复杂性。
    *   **应对**：提前进行技术调研和原型验证；严格按照支付平台官方文档进行开发和测试；引入有经验的开发人员。
2.  **安全风险**：
    *   **风险**：用户数据泄露、支付安全漏洞、恶意攻击。
    *   **应对**：采用成熟的安全框架和加密技术；定期进行安全审计和渗透测试；建立完善的安全管理制度。
3.  **性能风险**：
    *   **风险**：高并发场景下系统响应缓慢或崩溃。
    *   **应对**：进行合理的架构设计和性能优化；使用缓存减轻数据库压力；进行压力测试，提前发现性能瓶颈。
4.  **运营风险**：
    *   **风险**：歌手入驻积极性不高；用户使用频率低。
    *   **应对**：制定合理的分成政策和激励机制；进行市场推广和用户引导；持续优化产品功能和用户体验。
